# SEO audit, September 2026

A point-in-time SEO audit of the whole site, with a prioritized fix backlog at the end. It follows the July 23 and July 30 passes recorded in [`seo-aeo-audit.md`](./seo-aeo-audit.md), and it is the first audit since the 2026-09-16 move to the Catalog 97 shell. The durable rules stay in [`SEO.md`](../SEO.md); this file is the findings and the backlog, and its unchecked items will go stale the same way the design audit's did, so read the date first.

**Date:** 2026-09-22 · **Method:** source sweep of all 63 route segments, a production build and crawl of every sitemap URL on a local `next start`, and a frontmatter pass over all 206 posts.

## What I checked and how

I built the site with `npm run build` (the postbuild sitemap came out byte-identical to the committed one, 268 URLs), served it with `next start`, and crawled every sitemap URL plus 18 control URLs, which is 276 HTML documents in total. For each one I recorded the rendered title, description, canonical, robots and Open Graph tags, every JSON-LD block, the h1 count, images without alt text, and every internal link, and then I re-fetched all 387 unique internal link targets to find redirects and errors. Three parallel source sweeps read each `page.tsx`, its client component, and its segment files, and a script parsed the frontmatter of all 206 posts.

One limit to state up front. Production `isaacvazquez.com` is unreachable from the sandbox this ran in, so anything that only exists in production is unverified here, including live response headers, the `www` and retired `isaacavazquez.com` redirects, Cloudflare and Netlify cache behaviour, Search Console coverage, and field Core Web Vitals. Everything below comes from the code and the local production build.

## What is in good shape

The July work held up in most of the places that matter. All 268 sitemap URLs return 200 with a self-referencing canonical, a unique title and description, an `index, follow` robots tag, `lang="en"`, one page-level `main`, alt text on every image, and JSON-LD that parses. 267 of the 268 have exactly one `h1` and a `BreadcrumbList`, and the one exception is a real defect covered below. The four internal surfaces (`/search`, `/admin`, `/analytics-reference`, `/design/catalog-pages`) are `noindex`, the 404 page returns a real 404 with `noindex` and no canonical, and the legacy `/blog`, `/projects`, `/work`, and ten retired project paths are single-hop 308s.

The sitemap is generated from the route tree, drops anything that opts out or redirects, holds future-dated posts back, and derives `lastmod` from the snapshot for every data dashboard, with a Jest test guarding the inventory. The crawler policy in `robots.txt` is deliberate (retrieval bots allowed, training bots blocked, `/api/rss` and `/_next/static` explicitly allowed) and also tested. Every post carries `Article` schema with author, both dates, an image, and a word count, the `Person` entity is shared by one `@id`, the RSS feed has all 206 items with autodiscovery, an IndexNow key file is published, `llms.txt` exists, and HTML is kept out of the CDN cache so snapshot refreshes show up. The fantasy rankings board deliberately ships its first page of rows in the HTML. On the content side, no post is under 400 words, the median is 975, and there are no duplicate titles or excerpts across the 206.

## The four things I would fix first

The portfolio index links every project through a temporary redirect. `Catalog97Portfolio.tsx` links each of the 33 project titles to `/portfolio/<slug>` (lines 256 and 363), and the homepage's three featured cards do the same (`Catalog97Home.tsx` lines 140 and 147). Every one of the 33 case studies in `caseStudies.ts` carries a `link`, and `src/app/portfolio/[slug]/page.tsx:102` answers with `redirect(caseStudy.link)`, which is a 307. The crawl found 33 redirecting internal link targets, 32 of them 307 and one 308 (the config already covers `investment-analytics-platform`). The July audit recorded zero redirecting links, so this is a regression from the Catalog 97 rebuild. The fix is small. Link to `project.link` when it exists, switch the page to `permanentRedirect`, and I would move all 33 into `next.config.mjs` next to the retired slugs so the redirect never has to render a page. `generateStaticParams` currently prerenders 33 redirect-only pages with full article metadata, which can go too.

The trade calculator is an empty page to anything that does not run JavaScript. `/fantasy-football/trade-calculator` is statically prerendered, and `TradeCalculatorClient` calls `useSearchParams()` at its top level (`trade-calculator-client.tsx:233`) with no Suspense boundary, so Next bails the page out to client-side rendering. The served HTML has the right title and meta tags and then 38 words of body, which is the header and footer. There is no `h1` and the two JSON-LD blocks exist only inside the React payload, never as script tags. The siblings like `/nba` avoid this because their `page.tsx` reads `searchParams` server-side, which makes the route dynamic. Either do the same here or wrap the hook consumer in a Suspense boundary whose fallback renders the heading and the intro. I would also add a no-JavaScript assertion to `e2e/fantasy-trade-calculator.spec.ts` so it cannot come back.

The old tier redirects now return 200 pages that claim to be the homepage. `/fantasy-football/rb-tiers` and `/fantasy-football/tiers/[position]` call `permanentRedirect()` in a server component, but the segment has a `loading.tsx`, so the shell streams first with a 200 status and the redirect is encoded in the payload for the client router (`NEXT_REDIRECT;replace;/fantasy-football?position=rb&scoring=ppr;308`). What a crawler receives is the root layout's homepage title, homepage description, and a canonical of `https://isaacvazquez.com`, all `index, follow`. The sitemap generator skips both routes correctly, but any inbound link or old share lands on an indexable duplicate of the homepage instead of consolidating to the rankings board, and `/tiers/[position]` has no `generateStaticParams`, so that set of URLs is unbounded. Both belong in `next.config.mjs` as permanent redirects beside the existing `/qb` and `/rb` aliases, with the page files deleted.

The title and description helpers are clipping most of the site mid-sentence. `fitSearchTitle` budgets 44 characters before the brand suffix, and the writing and portfolio routes apply it, so 188 of the 206 post `<title>` tags end in an ellipsis and `og:title` inherits the same string, for example "Owning a Peer-to-Peer Texting Platform Used… | Isaac Vazquez". 104 of the `seo.title` values are over 60 characters on their own, so there is an authoring problem underneath the helper problem. `fitMetaDescription` does the same at 160, and 192 rendered descriptions end in "…", which is 169 posts plus 23 tool pages (the tool pages are listed in the backlog). The July audit counted the 60 and 160 caps as a pass. I'd argue a mid-word ellipsis is worse than a slightly long tag, since Google truncates by pixel width on its own, every keyword past character 44 disappears from the tag entirely, and the ellipsis shows up on every social card. My recommendation is to stop truncating `<title>` at all and instead drop the brand suffix when the unbranded title runs past about 50 characters, to hold post `seo.title` values under roughly 55 characters going forward, and for descriptions to choose whichever of `seo.description` and `excerpt` fits under 160 rather than clipping, with a test that fails on an over-long description instead of a helper that hides it.

## Freshness signals that have drifted

The seven designed routes were rebuilt on 2026-09-16 (and `Catalog97Home` changed again on 09-21), but `STATIC_ROUTE_LASTMOD` in `src/lib/sitemap.js` still says 2026-08-05 or 08-09 for `/`, `/about`, `/portfolio`, `/writing`, `/dashboards`, `/resume`, and `/contact`, and each page's `dateModified` says the same. Sixteen posts stamped `publishedAt: 2025-01-24` carry no `updatedAt`, even though `CLAUDE.md` records the April 2026 voice rewrite of the original articles, so their sitemap `lastmod` and `Article.dateModified` both say January 2025. All seven writing topic pages share a fixed 2026-06-22 `lastmod` while listing posts published through September. `/news-pulse` and `/mba-internship-notifications` hardcode `dateModified: "2026-07-23"` in both the metadata and the schema while their descriptions open with "Live". `/fantasy-football/weekly` and `/waivers` fall through to the default `monthly` changefreq though they change weekly in season, and `/march-madness-2026` still promises upset picks and Final Four predictions with a March 17 date six months after the tournament ended. `/now` says "Updated June 2026".

I think the practical fix is to stop hand-maintaining dates for the designed routes and derive them from git or the build, to set `updatedAt` on the sixteen rewritten posts in one pass, to compute topic page `lastmod` from the newest post in the topic, and to reframe the March Madness page as a results and postmortem surface or point its metadata at what it now is. Google treats `lastmod` as a hint it can stop trusting, so the point of fixing these is to keep the dates that are accurate credible.

## Pages crawlers see mostly empty

Word counts in the served HTML, excluding the shell, run under 120 on five indexable pages: the trade calculator at 38, `/score-pools/tracker` at 85, `/fantasy-football/weekly` at 90, `/score-pools/settings` at 96, and `/fantasy-football/waivers` at 107. Beyond those, `/travel` and `/wine-cellar` render zero entries server-side because their stores hand the server an empty array snapshot, `/investments` renders its chrome and a heading while the holdings arrive from localStorage and a quotes fetch, and `/fantasy-football/best-ball`, `/draft-tracker`, and `/mock-draft` fetch their boards client-side even though the sibling `/fantasy-football` seeds its first page on the server on purpose. The weekly hook has no seed argument at all.

The question underneath is which of these should be indexable. `/score-pools/settings` and `/score-pools/tracker` are personal configuration surfaces, and `/travel` and `/wine-cellar` are single-user localStorage tools whose indexable page is an empty shell wearing `SoftwareApplication` schema. I would either `noindex` those four (the sitemap generator drops them automatically) or give each a real server-rendered paragraph that says what the tool does and why. For the fantasy pages, reuse the `loadFantasySnapshotSeed` pattern so the first rows ship in the HTML, and give the weekly hook an initial-snapshot parameter.

## Structured data

The `SportsApplication` branch in `src/components/StructuredData.tsx` (lines 139 to 181) has a fantasy football default baked in. When a caller passes no `about` or `audience`, the branch injects `about: "Fantasy Football"` and `audience: "Fantasy Football Players"`, and because the branch writes its own keys after the spread it also overwrites the caller's `applicationCategory`. Today that means `/golf`, `/premier-league`, `/score-pools`, and `/polling-aggregator` all declare themselves fantasy football products for fantasy football players, and the polling page's `NewsApplication` category is silently replaced. The `BreadcrumbList` and `FAQPage` branches spread `...data` after building the object, so 59 pages emit a nonstandard `items` property beside `itemListElement` and two emit `questions` beside `mainEntity`. Every `SoftwareApplication` also picks up a default `Offer` at 0 USD and `operatingSystem: Any` unless the caller overrides them, which puts a commercial offer on editorial pages like `/agent-build-index` and `/food-map`. None of this breaks parsing, and Google's software app rich result was never in reach without ratings, but the fantasy leak is wrong on its face and the fix is a few lines in one component.

Three fantasy pages (`/fantasy-football/weekly`, `/waivers`, and `/best-ball/draft-tracker`) emit two `BreadcrumbList` blocks because the shared navigation component `src/components/navigation/Breadcrumbs.tsx` writes its own JSON-LD at line 123 on top of the page's. `/march-madness-2026` emits `Article` and `FAQPage` while its Open Graph type stays `website`. Post `Article` nodes carry no `publisher`, which Google lists as recommended. `og:image:alt` is the generic site alt on every page, including the 206 posts with their own generated cards and the 21 routes with custom images, because `constructMetadata` reuses `siteConfig.ogImageAlt` for every image. Fifty page files hardcode `https://isaacvazquez.com` inside their JSON-LD and five pass an absolute `canonicalUrl`, which defeats the `SITE_URL` override the helper was built around and is the kind of thing that will point preview deploys at production. Finally, the `StructuredData` component's type union supports ten types, and any of the other five `SEO.md` still lists (ProfilePage, CreativeWork, ProfessionalService, Organization, JobPosting) would render a JSON-LD block containing only `@context`.

## Internal linking and orphans

Counting rendered links across the crawl, `/arcade` has one inbound link, from the changelog, and `/travel-deals`, `/score-pools/tracker`, and `/fantasy-football/best-ball/draft-tracker` have one each, with a dozen tool routes at two or three. Posts sit at a median of 6 inbound links with a floor of 2, and 14 posts are at 3 or fewer; the floor is the template's related and previous/next links doing the work. Inside the article bodies, 58 of 206 posts contain no internal link at all, 103 contain no link to another article, and the average is 2.1 body links per post. The `/writing` archive renders 30 archive rows in HTML and the rest behind a client-side "show more", so more than a hundred archive posts are reachable from the index only after hydration, though the topic pages and prev/next chains still cover them.

One taxonomy note, since it feeds the related-post selection. The 206 posts use 37 distinct `category` strings, including AI, Agentic AI, AI Tools, and AI & Analytics, and QA Engineering, Quality Engineering, and Software Quality. `getRelatedBlogPosts` scores a category match at ten points, so that fragmentation weakens the links the template chooses. Collapsing the categories to the seven cluster and bucket labels would probably improve related links more than any manual linking pass.

## Page weight and font loading

`/writing` ships 523 KB of HTML. 113 KB of that is a single `ItemList` JSON-LD block with all 206 posts including descriptions and image URLs, and 368 KB is the React payload carrying the same 206 posts a second time as props to the client component, on top of the rendered cards. `/golf` is 1.0 MB of HTML, `/github-trending-pulse` 430 KB, `/writing/topics/sports-fantasy` 420 KB, and `/fantasy-football` 304 KB. JavaScript is about 205 KB gzipped across 13 chunks on the homepage and 234 KB on the rankings board, which is ordinary for this stack. I would cap the `/writing` `ItemList` at the curated posts or the newest 30, drop its per-item descriptions, and pass the client component a lighter preview shape.

The font preload behaviour is the more surprising finding. Static routes (`/`, `/about`, `/now`, every post) emit two `woff2` preload hints. Every dynamically rendered route, which is all of the tool dashboards including `/golf`, `/mlb`, `/investments`, and `/fantasy-football`, emits none, even though the `layout.tsx` comment says Fragment Mono preloads because its chips sit above the fold on the tool routes and cites a CLS incident on the fantasy board from 2026-09-14. I could not run field vitals from here, so I would treat this as something to confirm with a Lighthouse pass on `/fantasy-football` and `/golf` before and after a fix.

## Metadata voice and smaller head issues

Of the 55 indexable static routes, 43 have descriptions in an impersonal or second-person register, and only 12 use the first person `WRITING_VOICE.md` asks for (`/`, `/about`, `/contact`, `/changelog`, `/dashboards`, `/accessibility`, `/resume`, `/writing`, `/portfolio`, and the three fintech tools). Several contradict their own ledes, so `/news-pulse` describes itself as a dashboard that "visualizes coverage patterns" while the page opens with "I built News Pulse to get a fast read on", and `/enablement-assistant`, `/ai-dev-tools`, and `/earthquake-pulse` do the same. `/now`, `/arcade`, and `/food-map` refer to Isaac in the third person. Fifteen routes also have an `h1` that shares few or no words with the title, including `/investments` ("Investments" against "Investment Research Platform"), `/fantasy-formula-1` (no overlap at all), and all seven topic pages, and `/museum-log` ends up with two pipes in its title.

In the head itself, every page carries two `viewport` and two `theme-color` tags because `layout.tsx` writes them by hand and Next adds its own, which the `viewport` export would resolve. The `hreflang="en-US"` self-reference on 273 pages does nothing on a single-language site, `og:updated_time` is not an Open Graph property, `/favicon.ico` returns 404, and `browserconfig.xml` points at four `mstile` icons that do not exist and a `/api/notifications/poll` endpoint that does not exist either. `manifest.json` still says "Technical Product Manager" and "mission-driven products through data-driven decisions", and the root social card that roughly 40 routes fall back to says "Building mission-driven products through data, user insight, and disciplined execution" on the blue gradient the design system retired.

## Machine-readable files and documentation drift

`public/llms.txt` has a typo in the Agent Build Index URL (`isaacavazquez.com`, the retired domain, on line 107), and its "Last reviewed: 2026-07-20" stamp is accurate, which means it omits the rent vs buy calculator, the trade calculator, best ball, waivers, the enablement assistant, the arcade, and the accessibility statement. The RSS feed is served as `application/xml` rather than `application/rss+xml`, puts an Atom `updated` element inside RSS items, and carries no `content:encoded`, so readers get the description only. `scripts/submitIndexNow.mjs` works but nothing calls it; `publish-data.yml` already knows when a deploy finished and could. `src/proxy.ts` still carries a `/blog` redirect branch that the config's 308 redirects run ahead of, so it is dead code, and it sets a second HSTS header with a different max-age than `next.config.mjs`.

`SEO.md` has drifted from the code in a handful of places worth correcting when the backlog lands. Its compliance table says the homepage emits `ProfilePage` (it emits `Person` and `WebSite`), that `/resume` emits `JobPosting` (it does not, and `seo-integrity.test.ts` forbids it), and that `/writing` emits an `Article` list (it is an `ItemList`). It says the `WebSite` schema includes a `SearchAction`, which it does not and should not since Google retired the sitelinks searchbox. It describes `generateAIOptimizedMetadata` as weaving expertise into the description when the function is now a thin wrapper that drops those fields. It tells you to uncomment a Search Console line that is now the `GOOGLE_SITE_VERIFICATION` environment variable. And it lists 15 preset schema types where the component handles 10.
