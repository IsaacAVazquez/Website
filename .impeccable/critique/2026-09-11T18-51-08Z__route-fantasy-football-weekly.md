## Priority Issues

1. [P2] The shared card lift moves the pinned header row and the whole board whenever the pointer or focus is inside the card. `.home-card:hover, .home-card:focus-within { transform: translateY(-4px) }` (`src/app/globals.css:1550-1555`) applies to the board section (`weekly-client.tsx:731`, `home-card p-5`). Measured at 1440 light, scrolled 3,000px: with the pointer at x=5 the card's `transform` is `none` and the first header cell's top is 73, flush with the site header's bottom; with the pointer over the table the transform is `matrix(1,0,0,1,0,-4)` and the same cell's top is 69, so the header row's top 4px sit behind the site header; moving the pointer off restores 73. Focus does the same without the pointer (search input focused, `:focus-within` true, transform applied). On this surface the card runs from x=32 to x=1408 and from 5,193px (default window) to about 19,000px (Show all) tall, so on a desktop the pointer is over it whenever the visitor is reading, and every entry and exit across its edge lifts and drops the entire board by 4px over 200ms. Why it matters: the morning fix put a page-level sticky header inside a card that is styled to move, and sticky is computed before transforms, so the offset the fix reserved for the site header is exactly 4px short in the state a desktop reader is in most of the time; the labels still show (the 30px cell has 8px of padding above the text) but the alignment the fix bought is not there when it is being used, and a 19,000px card lifting under the cursor is the wrong kind of liveliness on a reading surface. Fix: the board section should take `home-card-static` (`globals.css:1563`, the non-interactive counterpart with the same border, radius and surface and no lift), which `MetricCard`, `AuthorBio` and `StatusPanel` already use; if the lift is wanted on the two-line waivers card, leave that one alone. Suggested pass: quieter.

2. [P2] Show all drops keyboard focus to `body`. With focus on "Show all 457" and Enter pressed, the status line reads "Showing all 457 players", 457 rows render, and `document.activeElement` is `BODY`, because both buttons unmount when `remainingCount` reaches 0 (`weekly-client.tsx:943-973`). Load more keeps focus on itself because the same button persists ("Load more (297 left)" active after a click), so this is the one control on the page where a keyboard user is dropped to the top of the tab order with 337 new rows above them. Why it matters: Show all is the control a screen reader user reaches last, after every pill and the search box, and pressing it sends them back to the start of the document. Fix: give the status line `tabIndex={-1}` and move focus to it after Show all (it already announces the new count), or focus the row header of the first newly revealed player. Suggested pass: harden.

3. [P2] "Expert range" and "Rostered" are still undefined on the page. Carried from the morning critique with the same evidence (`:738-744`, `:849`, `:856`, `:129-132`), now also the phone labels at `:930` and `:934`, which repeat the two undefined names 120 times. The footnote fix means the only help text on the page is now true, which is why Help moves to 3, but the two columns that carry the lineup decision are the two without a sentence. Fix as before: one sentence in the panel note naming both readouts (lowest and highest rank any contributing expert gave; average share of leagues rostering the player, platform unnamed by the source), and a focusable trigger later if a column-level path is wanted. Suggested pass: clarify.

## Minor Observations

- The three 10px uppercase labels (`ReadoutPair`, `:178`, `text-3xs`) pass AA at 5.40:1 light and 6.00:1 dark, and "OPPONENT vs. NO" is a label on a value that already names itself. Dropping the opponent label and keeping the two numeric ones would lighten every phone row.

Same shape as the rankings board; worth a "Load more" that is also reachable from the status line if it ever matters.
