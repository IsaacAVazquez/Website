# Dashboard index surface brief

**Scope.** The `/dashboards` route, rendered by `src/components/catalog97/Catalog97Dashboards.tsx`. One of the seven Catalog 97 surfaces.

**Visitor mode.** Operate. Scanability and consistency outrank expression.

**Job / action.** Find the right instrument and open it.

**Route constraints.** The mosaic cycle is four wide with one Pine (`pine, camel, bone, camel`) so Pine does not take half of 33 tiles and the Pine tile walks diagonally across a three-column grid rather than stacking into a stripe. The status tile states the fail-soft convention rather than printing a snapshot timestamp, because no per-tool timestamp is readable at render time and inventing one is barred.

**Visual world: Catalog 97, not Working Instrument.** `DESIGN.md` describes The Working Instrument and governs the other ~40 routes. It does NOT govern this surface. `context.mjs` auto-loads it anyway, so a pass that treats it as the spec here will read every deliberate Catalog 97 decision as a violation and manufacture a page of false findings. Tokens live in `src/app/catalog97.css`.

**Do not re-litigate (settled 2026-08-02).**
- Tobacco is a large-text-only field. Paper ink on it is 4.36:1, which clears 3:1 for large text and never clears 4.5:1 for body. A tobacco band carries `--c97-fs-h2` (24px floor) and up, or no text at all. Not a defect; solved by size rather than by darkening the colour.
- Anton draws numerals at `--c97-fs-plate` only. Never running text, never headings, and there is no smaller numeral step. This replaced the earlier one-Anton-per-view rule.
- The scales are frozen: 9 type steps, 8 spacing values (`--c97-gutter` plus `--c97-sp-1..7`), 4 line heights, 3 measures plus `--c97-container`. `--c97-touch-y/x` sit outside the spacing ladder on purpose, solved backwards from the 44px floor.
- Every `--c97-*` value is declared under `[data-c97]` or `[data-c97-surface]`, never under a class, so a token consumer can skip class rules wholesale.
- Image slots render as flat Stone or Tobacco fields because no photograph exists yet. That is the design’s own layout rule, not an unfinished asset.

**Verified state.** 0 contrast failures across 2774 text nodes in both themes, each resolved against its own enclosing surface and backdrop. Zero shadows, zero radii above 2px, zero off-palette hex in components. `focus-visible` covers anchors, buttons, inputs, textareas, selects and summaries. Exactly one `aria-current` per route. Espresso footer present. No two Pine bands adjacent, and at least two brown bands per route.

**Commands worth running.** `critique` and `audit` to find. Then only what the findings name. `polish` last. Never `document` here (it would regenerate DESIGN.md against the wrong world), and never both halves of `bolder`/`quieter` or `overdrive`/`distill`.

**Settled 2026-08-02 (critique, degraded single-context).** The anchor reset is `:where(.c97-page) a`, not `.c97-page a`. At `.c97-page a` it scored (0,1,1) and outranked every single-class component rule, so each `.c97-btn` rendered as a `<Link>` discarded its own `color: var(--c97-surface)` and inherited the band ink instead. Measured live: "See the work" was espresso on chocolate at 1.4:1, and `.c97-btn-invert`, whose background is `--c97-ink`, was heading for 1:1 invisible text on six routes. All 13 buttons on the site are anchors, so all 13 were affected. Static token-math audits miss this because they read the declared rule rather than the winning cascade. Do not raise the `:where()` back to a plain class, and re-measure buttons in a browser after any change to the anchor reset.

**Settled 2026-08-02 (mobile pass).** The header wordmark carries `.c97-brand`, which applies the same padding-plus-negative-margin hit target as `.c97-microlink`. At 390px it measured a 23px tap target before this, under the 44px floor the rest of the site holds; it is 55px now. Dark mode is verified live rather than by token math: all eight surfaces render their derived dark values and both themes measure zero contrast failures. When re-measuring after a theme toggle, wait a tick before reading computed styles — reading in the same synchronous block returns the pre-toggle paint and looks like dark mode is broken when it is not.

**Settled 2026-08-03 (critique, degraded single-context). The route holds Operate and the visuals adapt to it.** Scored 21/40. The mosaic was doing Persuade work on a surface committed to Operate, and the resolution is to keep the Operate commitment and make the mosaic serve findability rather than to rewrite the brief toward Experience. What that means concretely is that the eight `classifyToolSlug` categories become the primary structure, as labelled runs with real section headings, and the four-surface cycle restarts per group so the first tile of every run shares a colour. Do not treat the cycle as settled in its current form. Its own comment is right that a straight pine/camel alternation put Pine on half of 33 tiles, and the cycle it chose instead runs in index order across group boundaries, so colour is the loudest signal on the page and is uncorrelated with the only structure the page has. Once the runs carry headings, the per-tile category kicker is redundant and comes off, and the tool titles demote from `h2` to `h3`.

**Fixed 2026-08-03, verified live.** The four issues above are implemented and measured in a browser, not inferred. The mosaic is eight headed runs, one per `classifyToolSlug` category, inside a single paper band; the per-tile category kicker is gone, because the heading names the run; tool titles are `h3` under the run's `h2`. The outline now reads one `h1`, nine `h2` at 32px, and 36 `h3`, so no child renders larger than its parent, and "How the data works" is a real `c97-h2` rather than an 11px label above 22px children. The status panel moved out of the grid onto its own paper band, so all 33 tiles are links and none of them is a decoy. `.c97-tile:hover` exists now and shifts the field toward its own ink; hovered Pine measured `rgb(31,68,63)` against a resting `rgb(13,53,49)` with `:hover` confirmed true on the element. The h1 reads "33 instruments I built, and I keep them running," and the route metadata names the browser-persisted tools separately. Contrast after the change is 11.26:1 and 9.72:1 on pine, 5.73:1 on camel, 11.44:1 and 8.18:1 on bone. Typecheck clean, 49 tests passing.

**Two corrections to the 2026-08-03 critique.** The critique said the snapshot overclaim also appeared in the footer colophon. It does not. The colophon says "The dashboards refresh nightly," which is true of the dashboards, and the same goes for the status copy's "Each dashboard" and the tobacco line's "Every panel here." Only the `h1` ("all") and the route metadata ("each") were wrong, and only those two were changed. Second, `.c97-tile:hover` reads back from the CSSOM as `var(--c97-surface)` rather than as the `color-mix` that is authored, because the build emits a fallback declaration in the same rule. The modern value still wins the cascade. Do not "fix" that reading; hover has to be measured on a genuinely hovered element, which is the same lesson as the anchor-reset entry above.

**Category filter added 2026-08-03, verified live.** The route is a client component now, for one piece of state and nothing else. The filter is deliberately the same control `/portfolio` runs over the same `classifyToolSlug` buckets, drawn the same way, so the two indexes do not diverge. Nine tabs with live counts, `role="tablist"` with `aria-selected`, and tap targets measuring 50px at 390px, clear of the 44px floor this site holds. The cycle offset is pinned to a group's position in the **full** list rather than the filtered one, so a run keeps its colours whether you are viewing all eight or that one alone; filtering changes what is on screen and nothing else. Verified: All is 8 runs and 33 tiles, Sports is 1 run and 11 tiles, returning to All restores both, and the Sports field sequence is byte-identical filtered and unfiltered.

**What the filter did and did not do to page length.** Filtered views are roughly half or less: at 390px, Sports is 5,572px (6.6 screens) and Lifestyle 4,463px (5.3), against 11,059px (13.1) for All. The default All view did not get shorter. It got 159px **longer** than before the filter, because the tablist itself costs that much, so the honest summary is 12.9 screens before and 13.1 now, with a one-tap route to about five. That is the intended trade and it should not be "fixed" by defaulting to a category or by collapsing runs on small screens. This route is the argument that Isaac has built and maintains 33 things, and a first view showing eight labels instead of the work undercuts the argument the page exists to make.

**Corrected 2026-08-03 (layout sweep). The tablist entry below was verified only at 1440 and was wrong on a phone.** The paragraph further down concludes that `--c97-sp-3` on both axes is correct and says the gap should not be changed. That holds at desktop, where `--c97-sp-3` is 32px and the wrapped rows sit 67px apart against 50px hit boxes. It does not hold on a phone. `--c97-sp-3` clamps to 22px at 320, which puts the rows 39px apart, and the control measured eight overlapping tap-target pairs there. The reasoning in that entry was sound and the measurement behind it was real, and the mistake was concluding "settled" from a single viewport. The tablist now carries `columnGap: var(--c97-sp-3)` and `rowGap: var(--c97-sp-5)`, and measures zero overlapping pairs at 320 with the rows 58px apart and zero at 1440 with them 86px apart. `/portfolio` and `/writing` run the same control and took the same change. Everything the entry says about tightening the gap remains true and still must not be done. The lesson worth carrying is that any `.c97-microlink` row which wraps has to be measured on a phone, because the spacing scale clamps down while the hit target derived from the 44px floor does not.

**Still open.** Freshness is the one original finding nothing has touched, and it stays blocked on data rather than on design. `generatedAt` exists, but only inside individual snapshot modules (`bestBallSnapshot`, `bayAreaTransitSnapshot`, `earthquakeData` and others), each with its own accessor and shape, and a large share of the 33 have no snapshot at all because they are localStorage tools or calculators. Putting a real date on a tile means building a uniform per-slug timestamp accessor across 15-plus modules first. Until that exists the panel correctly states the convention, because inventing a date is barred. **The tablist wrap is closed, not open, and the earlier suggestion in this brief was wrong twice.** At 1440 the nine tabs wrap and leave "Lifestyle 6" on a second row. This brief previously said dropping the gap to `--c97-sp-2` would fit them on one line. It would not. Measured live, the buttons total 970px in the 1080px shell, so the widest gap that fits nine on one row is 13px, and the frozen scale has nothing between `--c97-sp-1` at 10px and `--c97-sp-2` at 17px. Single row is unreachable without breaking the scale. Tightening only the row gap was then tried as a way to make the wrap read as one block rather than a stray line, and it introduced a worse defect than the one it fixed: `.c97-microlink` buys its 44px target with padding plus negative margin, so each tab's hit box is 50px tall against about 17px of visible text, and a `--c97-sp-2` row gap put the rows 34px apart, at which point "Lifestyle" overlapped both "All" and "Fintech" by 15px vertically and 62px horizontally. That is a mis-tap introduced on a control whose only flaw was an uneven wrap. It was reverted. The gap stays `--c97-sp-3` on both axes, which holds the rows 49px apart with zero overlapping target pairs, and the reasoning is recorded in the component so it is not retried. Treat the uneven wrap as the correct resting state. The `isExternal` branch stays dead until a tool with an external link exists, and it will need a visible affordance and an accessible-name hint when one does. The hero kicker "Dashboards" above the `h1` is the pattern the craft floor bans outright, and it survives here because `.c97-kicker` is the committed Catalog 97 device across all seven routes; changing that is a design decision for the whole world, not a fix for one route.

**Tooling note for this surface.** `detect.mjs` returns `[]` with exit 0 on the component, on `src/components/catalog97/`, and on `catalog97.css`, which means nothing was matchable rather than that nothing is wrong. The in-page detector cannot be injected here at all, because the site's enforcing CSP (`script-src 'self' 'unsafe-inline' …`) blocks an external script tag. Do not weaken the CSP to run the tool. Measure the live DOM through Playwright instead, which is where every finding in the 2026-08-03 pass came from.
