# Catalog 97 tool shell surface brief

**Scope.** `src/components/catalog97/Catalog97ToolShell.tsx`, rendered by `ConditionalLayout` around every route that is not one of the seven designed Catalog 97 pages, `/admin` included. It is `Catalog97Shell` plus an optional title band and the build-note aside, so an edit here changes 57 routes at once.

**Visitor mode.** Operate. The shell is chrome around a working tool, so it should be quiet and let the dashboard or the calculator be the loudest thing on screen.

**Visual world: Catalog 97, not Working Instrument.** `DESIGN.md` still describes the Working Instrument as of 2026-09-16 and will until the close-out PR regenerates it. Judging this file or any route inside it against `DESIGN.md` manufactures false findings. Tokens live in `src/app/catalog97.css`.

**The bridge, and what it means for findings.** Every route inside this shell still renders components written against `--home-*` tokens. The bridge block in `catalog97.css` (between the `BRIDGE START` and `BRIDGE END` markers) aliases each of those onto the Catalog 97 value for the enclosing surface, zeroes the radii, removes the shadows, and swaps the fonts. So a finding that reads "this card uses `--home-paper-raised`" is not a defect on its own, since that token resolves to the bone field here. The defect to look for is a layout idea the bridge cannot repaint, meaning a signal-orange semantic that reads wrong as oxblood, a shadow drawn with a literal rgba, a raw hex, or a radius set in a Tailwind class like `rounded-xl` instead of through a `--radius-*` token. Those are what the family migrations exist to fix, and each family's PR is the place to record them. The shell wraps route content, the children and the build-note aside, in its own `data-c97-surface="paper"` element rather than relying on the `.c97-page` root's own attribute, because every surface-scoped rule in `catalog97.css` uses the descendant combinator `.c97-page [data-c97-surface…]`, which does not match an attribute sitting on the `.c97-page` element itself; without that inner wrapper, everything a route renders directly would sit outside any surface scope and keep the un-bridged Working Instrument colors.

**Status colour has a large-text-only rule on four surfaces.** Light camel, light stone, light tobacco, and dark stone are mid-tones, and the status tokens measure 3.45 to 4.00 on them. On those four the tokens are only used for marks or text at `--c97-fs-h2` and above, and body-size status text uses ink. The chip modifiers are stricter and stay in ink on camel, stone, and tobacco in both themes, since a chip is always label-size.

**The band is opt-in and off by default.** Every route on the site already draws its own `h1`, so the shell adds none. A family migration passes `band` when it moves a route's hero into the shell, and at that point the route's own `h1` must go, because the sweep asserts exactly one per route.

**Commands worth running.** `critique` and `audit`, on a route rendered inside the shell and not on this file, since the file has no visual content of its own. Never `document` here.

**Verified state (2026-09-16).** The Task 9 sweep hit 17 routes rendered inside this shell across all four states, light and dark theme crossed with a 390px and a 1440px viewport, 68 page loads total, and every one came back with exactly one `main`, exactly one `h1`, no horizontal overflow, and both the header nav and site footer present. The sweep script's own color parser needed two fixes before its contrast readings could be trusted: Chromium serializes color-mix() results as `color(srgb 0-1 0-1 0-1)` floats rather than legacy 0-255 `rgb()`, and serializes alpha-modified Tailwind utilities as `oklab(L a b / alpha)`, and the original regex-based parser read both as if they were already 0-255 sRGB, which manufactured hundreds of false contrast failures; the parser now converts both formats and composites partial-alpha backgrounds (the `--home-overlay` 8% ink wash in particular) up through the ancestor chain instead of stopping at the first non-zero-alpha layer. With that fixed, the sanity check on `/now` read the brand line at 13.25:1 for `#2b211a` on `#f1ebdf`, not the 10.9:1 this step's instructions predicted, but the hex pair matched exactly and the number is well inside plausible high-contrast range, so the parser is trusted rather than the prediction. A fix round 1 defect closed the gap this sweep first found: the shell now wraps route content in its own `data-c97-surface="paper"` element (see above), and reading `--home-ink-muted` off that element on `/nba` in the browser now returns the surface-mapped `#4a3728`, with `--home-signal` returning `#6e2b36`, instead of the pre-bridge Working Instrument values. The re-run sweep confirms it: the two `/nba`/`/premier-league` findings this closed no longer appear, and the two `/nba` desktop-viewport rows that previously carried five failures each (the whole standings table, now correctly bridged) are down to one. What's left is narrower and different in kind, two component-literal inline styles inside the shared football components that were never routed through the bridge's `--home-signal-soft` token in the first place, so the one fix available to this task does not reach them. `/nba` and `/premier-league` each fail one node in light theme, both viewports: a `text-xs text-[var(--home-ink-soft)]` conference-count pill ("15" on `/nba`, "20" on `/premier-league`) at 4.04:1 against a 4.5 floor, sitting on a pressed-toggle background set by an inline `style="background:color-mix(in srgb, var(--home-signal) 9%, var(--home-paper-alt))"`, a one-off mix baked into the component rather than the bridge's `--home-signal-soft` token. `/premier-league` also fails its `Champions League` chip in dark theme only, both viewports, at 4.11:1, styled inline as `color:var(--home-signal)` on `background:color-mix(in srgb, var(--home-signal) 10%, var(--home-paper-alt))`, again a component-literal mix independent of `--home-signal-soft`. `/food-map` still fails 47 nodes in light and 38 in dark against its own out-of-scope palette, and `/admin` still renders its sign-in view (`h1` "Admin Access") cleanly at 0 fails in every state.
