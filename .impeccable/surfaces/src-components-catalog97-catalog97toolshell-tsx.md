# Catalog 97 tool shell surface brief
Checked against the code on 2026-11-02.

**Scope.** `src/components/catalog97/Catalog97ToolShell.tsx`, rendered by `ConditionalLayout` around every route that is not one of the seven designed Catalog 97 pages, the 404 included. It is `Catalog97Shell` plus the build-note aside, so an edit here changes all of those routes at once, 55 `page.tsx` files under `src/app` on 2026-11-02 (`find src/app -name page.tsx` lists 62, less the seven). `/admin` was one of them until it was deleted on 2026-10-02 (7214f1fca). The aside is `src/components/ProjectBuildNote.tsx`, loaded through `next/dynamic` only where `projectBuildNoteLinks` has an entry for the path, and it prints as its own bone `c97-sheet` with a deckle seam, holding an h2, one paragraph, and the "Read the build notes" link. The h2 reads "What I use it for" where `PROJECT_BUILD_NOTE_CONTEXT` has the route and "Why I built it this way" otherwise, and `src/components/__tests__/ProjectBuildNote.test.tsx` pins both. `src/components/catalog97/__tests__/Catalog97ToolShell.test.tsx` pins the "Main" nav, a `main` with id `main-content`, the "Site footer" contentinfo, exactly one h1 inside the paper wrapper, and the build-note link inside `main`.

**Visitor mode.** Operate. The shell is chrome around a working tool, so it should be quiet and let the dashboard or the calculator be the loudest thing on screen.

**Visual world: Catalog 97.** `DESIGN.md` now describes Catalog 97 as shipped, so judging this file or any route inside it against `DESIGN.md` is correct. Tokens live in `src/app/catalog97.css`. As of 2026-11-02 that holds for the frame, the build-note aside, and the utility pages, articles and topic pages inside the shell. Since 2026-10-11 a project route owns its design inside the paper wrapper and is judged against the "Project routes" section of `DESIGN_CHECKLIST.md`, which names the routes it covers. That section allows a route its own `--<abbr>-*` custom properties with a light and a dark story, such as `--f1-*` in `src/app/formula-1/formula-1.module.css`, so a hex value declared in one is not a finding by itself, and the next paragraph's line that every route here renders against `--c97-*` tokens describes the state before that date.

**No bridge, and what that means for findings.** The Working Instrument, its `--home-*` tokens, and the bridge block that used to alias them onto Catalog 97 values were deleted on 2026-09-27; `src/app/__tests__/catalog97-closeout.test.ts` fails if any file under `src` reads one of those tokens again. Every route inside this shell now renders components written directly against `--c97-*` tokens, so a finding that reads "this card uses `--home-paper-raised`" would be a real regression rather than a bridged non-issue. The defect to look for is a raw hex, a literal rgba shadow, or a radius set as an arbitrary value or an inline style. The `--radius-*` tokens were deleted on 2026-09-27 (486ea70cb), and since then `tailwind.config.ts` compiles the named radius and shadow utilities to `0` and `none`, so a leftover `rounded-xl` paints square and is only clutter to remove. The shell wraps route content, the children and the build-note aside, in its own `data-c97-surface="paper"` element rather than relying on the `.c97-page` root's own attribute, because every surface-scoped rule in `catalog97.css` uses the descendant combinator `.c97-page [data-c97-surface…]`, which does not match an attribute sitting on the `.c97-page` element itself; without that inner wrapper, everything a route renders directly would sit outside any surface scope.

**Status colour has a large-text-only rule on two surfaces.** Light stone and dark stone are mid-tones, and the status tokens measure 3.70 to 4.00 on them, computed from the token values in `catalog97.css` on 2026-11-02. On those two the tokens are only used for marks or text at `--c97-fs-h2` and above, and body-size status text uses ink. The rule covered light camel and light tobacco too until the 2026-09-23 repaint. On light ink-saffron the status tokens now clear 5.3:1, and on ink-vermilion, ink-green, ink-pink and ink-teal in both themes, and on ink-saffron and ink-peach in dark mode, every status token resolves to the ink. The chip modifiers are stricter, since a chip is always label-size. They colour a chip only on paper, bone and ink-blue, and on chocolate and espresso in dark mode, and everywhere else a chip keeps its ink, which is print black on light chocolate and light espresso.

**The band was opt-in and off by default.** Every route on the site already draws its own `h1`, so the shell adds none. A family migration passed `band` when it moves a route's hero into the shell, and at that point the route's own `h1` must go, because the sweep asserts exactly one per route. As of 2026-11-02 there is no `band` prop, since it was removed on 2026-10-02 (198e49312), so every route draws its own `h1` and the shell never adds one.

**Commands worth running.** `critique` and `audit`, on a route rendered inside the shell and not on this file, since the file has no visual content of its own. Never `document` here.

**Verified state (2026-09-16).** The Task 9 sweep hit 17 routes rendered inside this shell across all four states, light and dark theme crossed with a 390px and a 1440px viewport, 68 page loads total, and every one came back with exactly one `main`, exactly one `h1`, no horizontal overflow, and both the header nav and site footer present. The sweep script's own color parser needed two fixes before its contrast readings could be trusted: Chromium serializes color-mix() results as `color(srgb 0-1 0-1 0-1)` floats rather than legacy 0-255 `rgb()`, and serializes alpha-modified Tailwind utilities as `oklab(L a b / alpha)`, and the original regex-based parser read both as if they were already 0-255 sRGB, which manufactured hundreds of false contrast failures; the parser now converts both formats and composites partial-alpha backgrounds (the `--home-overlay` 8% ink wash in particular) up through the ancestor chain instead of stopping at the first non-zero-alpha layer. With that fixed, the sanity check on `/now` read the brand line at 13.25:1 for `#2b211a` on `#f1ebdf`, not the 10.9:1 this step's instructions predicted, but the hex pair matched exactly and the number is well inside plausible high-contrast range, so the parser is trusted rather than the prediction. A fix round 1 defect closed the gap this sweep first found: the shell now wraps route content in its own `data-c97-surface="paper"` element (see above), and reading `--home-ink-muted` off that element on `/nba` in the browser now returns the surface-mapped `#4a3728`, with `--home-signal` returning `#6e2b36`, instead of the pre-bridge Working Instrument values.
