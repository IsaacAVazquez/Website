# Project Solara Puts Microsoft's Agents on Android Devices Beyond the PC

Build's headlines went to the seven models Microsoft AI trained in-house and to Scout, an always-on work agent that [TechCrunch read mainly as Microsoft adapting the open-source agent OpenClaw](https://techcrunch.com/2026/06/02/microsoft-launches-scout-an-openclaw-inspired-personal-assistant/) for enterprise use. At the same event on June 2, Microsoft unveiled Project Solara, a platform for agent devices built on the Microsoft Device Ecosystem Platform, or MDEP, an enterprise operating system based on the Android Open Source Project. Solara read as a hardware curiosity, and Steven Bathiche, who leads the effort, [said Microsoft is still early](https://commandline.microsoft.com/project-solara-build-2026/) and didn't want to overpromise. I think the most revealing platform decision of the event was taking MDEP, which Microsoft had used for shared meeting-room hardware, and making it the base of personal agent devices sold as a platform, because that change of scope amounts to the company that, at Computex on June 10, claimed [more than a billion daily Windows users](https://blogs.windows.com/devices/2026/06/10/computex-2026-empowering-a-billion-users-with-windows-across-the-ecosystem/) conceding that the endpoints of the agent era won't all be PCs. I'd argue it's the right concession, since the agents Microsoft sells have to reach workers who spend their shifts on their feet, and the identity and governance that make those agents sellable already live in Entra, Intune, and Agent 365, Microsoft's identity, device management, and agent oversight services.

## The badge and the desk companion

Microsoft calls [Solara](https://commandline.microsoft.com/project-solara-build-2026/) a chip-to-cloud platform for agent-first devices, and it showed two reference designs. One is a wearable badge on Qualcomm silicon with 5G and a far-field microphone array, and the other is a desk companion on MediaTek silicon that can pair with a Windows PC or act as a Windows 365 client for a cloud-hosted Windows PC. It runs Microsoft 365 Copilot, Researcher, Facilitator, and Priority Agent, the GitHub Copilot and Dragon Copilot teams are exploring what they could do on it, and Microsoft said it hopes third-party agents will follow. Microsoft said pilots would begin "in the coming months" with companies including AccuWeather, Best Buy, CVS Health, Levi's, and Target, with no availability date.

Four of the five pilot companies Microsoft named run stores or pharmacies, and the badge's hardware, a cellular radio plus microphones built to pick up a voice across a room, fits someone who talks to an agent while walking a sales floor or working a pharmacy counter. Dragon Copilot, Microsoft's voice assistant for clinicians, points the same way, since clinical work happens in exam rooms and on hospital wards. Microsoft pitched Solara to information workers as well as nurses and frontline staff, and its launch agents are knowledge-work tools, but my reading of the badge and the pilot list is that it's aimed at workers a PC never fit, while the desk companion keeps Solara tied to the PC for everyone else.

## Windows keeps the desk

The same day, Microsoft announced [Microsoft Execution Containers](https://blogs.windows.com/windowsdeveloper/2026/06/02/windows-platform-security-for-ai-agents/), a policy-driven layer over Windows' own isolation features for agents that run locally, OpenClaw adopted them to run on Windows, and agents get distinct identities governed through Entra and Intune. Scout [runs under its own Entra identity](https://www.microsoft.com/en-us/copilot/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/) and follows Purview data policies, and it can't be switched on without an Intune policy.

I think Microsoft is separating where agents run from which operating system it owns. Windows keeps desk work, where local agents need containment, and the identity and policy come from Entra and Intune wherever the agent runs. Microsoft [announced MDEP in March 2023](https://techcommunity.microsoft.com/blog/microsoftteamsblog/whats-new-in-microsoft-teams-rooms-and-devices-at-enterprise-connect/3770137) as its Android build for Teams devices in shared spaces like meeting rooms, with native support for Intune's Android management. The plainest reading is that MDEP was simply the default, since Windows isn't built for a device the size of a badge, Microsoft already reaches phones through its Copilot apps, and Microsoft gave no reason for the choice. I think that's probably right about the operating system, but it misses the change of scope, from shared room hardware to devices a single worker carries, which is a decision about where Microsoft expects its agents to be used. I argued in November that what Microsoft sells enterprises is [the governed layer around the models](/writing/microsoft-ignite-agent-365-governed-layer), meaning the identities, permissions, and registry every agent needs, and Solara reads to me like that decision carried from software into hardware.

## The device history objection

The best argument that Solara goes nowhere starts with Microsoft's own record, from Windows Phone, to the Band, to HoloLens, and adds that a pilot with a retailer is a long way from a product, and that the phone is already the agent device people carry. Building on AOSP gives Google influence over the code under Microsoft's devices, and a second device platform splits Microsoft's story at the moment it is pitching Windows as a secure home for agents. On April 29, Microsoft [told investors](https://www.microsoft.com/en-us/investor/events/fy-2026/earnings-fy-2026-q3) to expect Windows OEM and Devices revenue, the line that combines what PC makers pay to license Windows with Microsoft's own devices, to decline in the mid to high teens in the quarter ending in June, with about 6 points of that from a PC market shrinking as memory costs push prices up, so a device bet that skips Windows can look like it weakens a franchise already under pressure.

I'd hold Solara to the filter I used on CES in January, when I argued that [a staged demo is the least reliable signal at a show](/writing/ces-2026-what-mattered), and a reference design shown on a stage says as little about daily use as a booth demo does. Where I think the history argument breaks is the job. Windows Phone needed outside developers to build for a third phone platform, and they never came, while Solara is a thin endpoint for Copilot services Microsoft already bills, so it needs far fewer third-party apps to be useful.

Of the other objections, the Google point matters least to me, since AOSP is Android's open-source code without Google's own services, and while Google still steers the upstream code, Microsoft controls the build that ships on these devices. The phone objection is the one I'd weigh most, so the pilots have to show that a hands-free 5G badge does a job the phone in a worker's pocket does badly. The split story is the objection I'd most want Microsoft to answer, since it pitched Windows as a secure place to run agents on the same day it unveiled agent devices built on Android. I also think the OEM guidance is weaker evidence against Solara than it looks, since most of the decline comes from inventory and from a year-earlier quarter lifted by Windows 10's end of support, while the 6 points Microsoft put on a PC market shrinking under memory costs are at least a reason not to tie every agent to a PC.

The logic of Build is that Microsoft is following the work off the desk. Its agents carry their identity and policy from Microsoft's cloud, so a device only has to put them in front of whoever is doing the work, and for a store associate or a nurse, I don't think that was ever going to be a PC. What I'd watch is whether the pilots turn into orders with a price and a date, which would move Solara from a reference design to a product. Until then I'd count it as the right read of where the work is and an open question about whether Microsoft can sell the hardware that follows it.
