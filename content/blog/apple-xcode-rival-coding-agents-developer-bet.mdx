# Letting Rival Coding Agents Into Xcode Keeps Apple at the Center of How Apps Get Built

On February 3 Apple shipped a release candidate of Xcode 26.3, the app developers use to build software for Apple's platforms, with Anthropic's Claude Agent and OpenAI's Codex built in, and eight days later [Bloomberg reported](https://www.bloomberg.com/news/articles/2026-02-11/apple-s-ios-26-4-siri-update-runs-into-snags-in-internal-testing-ios-26-5-27) that the Gemini-backed Siri upgrade had run into problems in internal testing and was slipping past iOS 26.4. When Apple's stock fell about 5 percent the next day, its worst session since April 2025, [CNBC tied the drop](https://www.cnbc.com/2026/02/12/apple-stock-worst-day-ftc-siri.html) to that report and to an FTC warning letter about Apple News. The delay got most of the attention, and coverage of the Xcode release was more positive and mostly stayed on what it meant for developers. [TechCrunch reported](https://techcrunch.com/2026/02/03/xcode-moves-into-agentic-coding-with-deeper-openai-and-anthropic-integrations/) that Apple worked closely with both labs on it and built it on the Model Context Protocol, an open standard for connecting AI agents to tools, and [VentureBeat called](https://venturebeat.com/technology/apple-integrates-anthropics-claude-and-openais-codex-into-xcode-26-3-in-push) the move to an open protocol a departure for a historically closed company while quoting security skeptics. I think Xcode was the more important story, and probably Apple's best AI decision of 2026 so far, because it makes Apple the place where agents build software for its platforms, and the relationship with developers is what actually sustains the iPhone.

## What the agents get inside Xcode

[Apple says](https://www.apple.com/newsroom/2026/02/xcode-26-point-3-unlocks-the-power-of-agentic-coding/) the agents in Xcode 26.3 can search documentation, explore a project's file structure, update project settings, and check their own work by capturing Xcode Previews and iterating through builds and fixes, and Xcode exposes those capabilities through the protocol for any compatible agent. TechCrunch reported that developers sign in with their own Anthropic or OpenAI account or add an API key, which leaves the billing relationship between the developer and the lab. I use Claude to write implementation code for the tools on my own site, and in my experience the environment an agent works in matters about as much as the agent does. In September 2025 I argued that [agents hold up in production when the task is scoped, verifiable, and limited to a defined set of tools](/writing/agentic-ai-production-reality-check-fall-2025), and Xcode's tools make the work verifiable, since an agent that can build the project, fix what breaks, and look at a preview can check its own work. The tools condition is looser, because each agent brings its own harness. [Anthropic says](https://anthropic.com/news/apple-xcode-claude-agent-sdk) Claude in Xcode runs on the Claude Agent SDK, the harness behind Claude Code, so Xcode adds tools to the agent without limiting it to them. For coding, Apple chose to be the venue for agents and left the model race to the labs.

## The open protocol makes the agent replaceable

What makes this a platform decision is the protocol. Because Xcode's capabilities sit behind an open standard, the agent becomes the piece a developer can swap, and Apple keeps everything around it, from its software development kits and documentation, to the build, test, and preview tools, to code signing and the review every App Store app goes through. None of that changes when a developer moves from Claude to Codex or to another agent that speaks the protocol, and the app still ends up on Apple's platforms, which Apple put at more than 2.5 billion active devices when it [reported its December quarter](https://www.apple.com/newsroom/2026/01/apple-reports-first-quarter-results/) on January 29. I'd argue the apps are a large part of what makes those devices worth owning, and the devices are what make the apps worth building.

The case against the move is that Apple has put two other companies between itself and its developers. The developer's account, billing, and daily habits belong to Anthropic or OpenAI, and an agent that can change project settings and run builds is a new security surface inside Apple's own tool. A skeptic would add that Apple let the labs in because it couldn't build a competitive coding model of its own. I'd concede the dependency and the security surface, and the skeptic may well be right about the model, but I still think Apple gave away the right piece. A developer can switch agents without giving up Xcode if one lab raises its prices or another builds a better agent, and Apple controls what Xcode hands to the agents, which is the part of the security risk a venue's owner can manage, while the rest of each agent's harness stays with the lab. Owning the place where agents work is worth more to Apple than owning any one agent, because developers can swap agents and can't swap the platform they are building for.

## The Siri slip in the same month

Siri is the useful contrast, because Apple relies on another company's model there as well and made a different choice about what to keep. Under the [January 12 joint statement](https://blog.google/company-news/inside-google/company-announcements/joint-statement-google-apple/) with Google, the next generation of Apple Foundation Models will be based on Google's Gemini models and cloud technology. There Apple keeps the assistant, so it answers for every response and has to hold any feature that isn't ready. Bloomberg's report describes features that aren't ready, with Siri sometimes misprocessing queries, taking too long to respond, or falling back to ChatGPT instead of the Gemini-based system in testing, and these are features Apple first promised in June 2024 and delayed in March 2025. With Xcode, Apple kept the venue and left the agents as other companies' products, so it could put a release candidate in developers' hands without building the agents itself.

Apple's own engineers seem to work the Xcode way already. Bloomberg's Mark Gurman [said on the tech show TBPN on January 29](https://9to5mac.com/2026/01/30/apple-runs-on-anthropic-says-mark-gurman/) that Anthropic powers much of Apple's internal product development and tooling, including custom versions of Claude on Apple's own servers, and that talks with Anthropic over a Siri deal fell apart over price. In developer tools Apple has been realistic about which parts it should build and which it should bring in, and with Siri, even with the model rented, it is still trying to build more of the product than it has been able to ship. In December I argued that [putting Apple Music inside ChatGPT](/writing/apple-music-in-chatgpt-assistant-entry-point) was a warning for Siri, since it moved one more everyday request into a rival's assistant, and Xcode runs the other way, with outside agents coming into Apple's tool to do their work.

The lesson I'd want Apple to carry from Xcode to Siri is that Apple does best as the place where the work happens, the owner of the context, the permissions, and the path to the customer, and that role doesn't require Apple to make the intelligence doing the work. Becoming the place where the work happens is harder on the iPhone than in Xcode, because Xcode had years of documentation, build tools, and previews ready for the agents, while the personal context, on-screen awareness, and in-app actions that would make the iPhone that kind of place for an assistant are the same features Bloomberg says are running into problems in testing. I don't know whether Apple gets those working in 2026, but I'd judge its AI year by whether they work, whoever's model sits underneath, and Xcode 26.3 is decent evidence that Apple knows how to build around an agent it doesn't own.
