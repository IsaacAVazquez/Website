# Anthropic's Most Important October Launch Was a Folder of Instructions

Anthropic shipped two things in the middle of October, and the one that got the headlines was Claude Haiku 4.5, which TechCrunch [treated as a cost and speed release](https://techcrunch.com/2025/10/15/anthropic-launches-new-version-of-scaled-down-haiku-model/). I think the launch that actually changes how companies build on Claude came the next day, on October 16, and it was a folder of instructions. Agent Skills let a team write a procedure down as a plain folder, with instructions, scripts, and reference files that Claude pulls in only when a task calls for them, and the same folder works in the Claude apps on paid plans, Claude Code, the API, and the Agent SDK. What that means is that customizing Claude moves from wiring up tools to writing down how the work gets done. I'd argue that's the right platform bet for a company that counts its business customers in the hundreds of thousands, and it holds only if the sandbox underneath it holds.

Haiku 4.5 is the easier case. Anthropic's [announcement](https://www.anthropic.com/news/claude-haiku-4-5) put it at 73.3% on SWE-bench Verified, which it described as coding performance similar to Sonnet 4 at a third of the price and more than twice the speed, and it lists at $1 and $5 per million input and output tokens. But an edge built on price and speed against your own older model is about the quickest kind for a competitor to close, and Simon Willison wrote on launch day that Haiku 4.5 already costs more than the cheapest models from OpenAI and Google. So I'd call it a good release whose advantage I wouldn't expect to hold for long.

Skills are the case that matters more. A skill is a folder with a `SKILL.md` file of instructions plus whatever scripts and resources it needs, and until a task calls for it, only the skill's name and a short description sit in Claude's context, with the full instructions and files loading when a request matches. What's interesting to me is that Anthropic [shipped its own skills](https://claude.com/blog/skills) for Excel, PowerPoint, Word, and fillable PDFs in that same format, and it named Box, Canva, Notion, and Rakuten as early users. Willison argued the day Skills launched that they [might end up mattering more than MCP](https://simonwillison.net/2025/Oct/16/claude-skills/), the Model Context Protocol Anthropic released in 2024 for connecting models to tools and data, because each one costs only a few dozen tokens until it's needed. I wrote in September that [agents hold up when the task is scoped, verifiable, and limited in the tools it can reach](/writing/agentic-ai-production-reality-check-fall-2025), and a skill is close to a file format for handing an agent that kind of task, with written steps for the judgment calls and scripts for the parts that should run the same way every time.

The business side is why I'd call this the platform decision of the month. Standing up an MCP server is engineering work, while a skill's instructions are plain language that the person who owns a job can write and fix. The more than 300,000 business customers Anthropic cited on October 23, repeating the figure from its September funding announcement, are far more companies than any vendor could hand-build workflows for, but Anthropic can let each customer write down its own know-how as skills that pile up on Claude over time. That's a different bet from the one OpenAI made on October 6, when it [used DevDay to turn ChatGPT into the surface where other companies' software runs](https://openai.com/index/introducing-apps-in-chatgpt/). OpenAI is betting on owning the place where people start their work, and Anthropic's October looks like a bet on being the best place to run the procedures a company writes down, from the chat app, to the terminal, to the API.

The launches around Skills show the plan in shipped product. On October 9, a week before Skills, Anthropic put [Claude Code plugins](https://claude.com/blog/claude-code-plugins) into public beta, bundling slash commands, subagents, MCP servers, and hooks into packages a developer installs with a `/plugin` command and can pull from any git repository that hosts a marketplace file. I think git is the right channel for a plugin format in October 2025, because it's where teams already review and version what they share, so their conventions can travel the same way their code does. Then the industry launches arrived with skills inside them. [Claude for Life Sciences](https://www.anthropic.com/news/claude-for-life-sciences) on October 20 paired connectors to Benchling, PubMed, 10x Genomics, and others with a skill for quality control on single-cell RNA sequencing data, and the [financial services push](https://www.anthropic.com/news/advancing-claude-for-financial-services) on October 27 added a Claude for Excel beta for Max, Team, and Enterprise users, starting with 1,000 users from a waitlist, along with live data connectors and six skills for work like discounted cash flow models and comparable company analysis. Both launches cited Sonnet 4.5's benchmark scores, so what Anthropic is selling into these industries looks like connectors and written procedures packaged on top of the same general model every other customer gets, and the procedures are the part a customer can write itself.

The strongest objection is that a format this open is just as easy for a competitor to use as it is for Anthropic. A skill is markdown and a few scripts, and Willison pointed out in his launch-day post that nothing stops other models from using the same folder, so a library of skills written for Claude doesn't lock anyone in the way a fine-tuned model or a proprietary integration would. I'd concede that completely, and I'd add that a procedure tested against how Claude behaves doesn't move as easily as the file does, so the company that runs those procedures best is in a strong position whether or not anyone is locked in. The safety objection is harder to wave away. Anthropic's own launch told people to install skills only from trusted sources, because skills can run code, and Willison said in the same post that the design depends on a filesystem and code execution that have to be sandboxed against prompt injection. A skill pulled from a stranger's repository is exactly that risk, and plugins already treat any git repository as a place to install from. Anthropic's [sandboxing write-up](https://www.anthropic.com/engineering/claude-code-sandboxing) for Claude Code on October 20, with filesystem and network isolation that it said cut permission prompts by 84% in its own internal use, is the right kind of answer, but I'd expect a bank's security team to see a supply-chain risk before it sees a platform, and I think that's a fair first reaction.

What I'd take from October is that the asset worth watching is the written procedure. I'd expect small models to keep getting cheaper at every lab, but the instructions a company writes for how it builds a cash flow model or checks a sequencing run are its own, and they get better each time someone fixes a step. Anthropic chose to keep those procedures in plain folders that work the same way across the Claude apps, Claude Code, the API, and the Agent SDK, which I think is the right call, and the part I'd watch is whether the sandbox is strong enough that security teams let their people install skills at all.
