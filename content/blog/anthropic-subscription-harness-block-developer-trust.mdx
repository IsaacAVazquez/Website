# Anthropic Drew the Right Line on Subscriptions and Enforced It the Wrong Way

Since third-party coding tools stopped working on Claude subscriptions on the evening of January 8, Pacific time, the argument has mostly been about whether the rule is fair. David Heinemeier Hansson, the creator of Ruby on Rails, called the move "very customer hostile" in a post on X that [VentureBeat quoted](https://venturebeat.com/technology/anthropic-cracks-down-on-unauthorized-claude-usage-by-third-party-harnesses), and an essay saying Anthropic made a mistake in cutting off third-party clients reached the front page of Hacker News on January 12. The Hacker News thread on the breakage became an argument over whether a $200 a month plan is a subsidy Anthropic is entitled to protect or plain vendor lock-in. I think the line is the half Anthropic got right. The half it got wrong is how it enforced the line, overnight and with no notice, and for a company whose growth runs through developers I'd argue that mistake costs more than the fight over fairness does.

The line itself holds up, and the reason is how the plans are priced. Tools like OpenCode, called harnesses because they wrap a model in their own interface for writing code, had been running on flat-rate Pro and Max subscriptions by identifying themselves as the Claude Code client. Those plans cost between $20 and $200 a month, and I think that price only makes sense as the price of Anthropic's own clients, whose usage Anthropic can see and tune. The one that matters most is Claude Code, which Anthropic's [January 13 Labs post](https://www.anthropic.com/news/introducing-anthropic-labs) says grew from a research preview into "a billion-dollar product in six months," where the billion is a run-rate, meaning recent revenue projected over a full year, that Anthropic disclosed in December. Since January 12 the flat plans have also carried [Cowork](https://simonwillison.net/2026/Jan/12/claude-cowork/), first on Max and from January 16 on Pro, which Anthropic bills as "Claude Code for the rest of your work." Pay-per-use access through Anthropic's API still works in any tool, so what the block took away was the flat price, and a flat price that any tool can draw on by claiming to be Claude Code works like an API with no meter. Anthropic's Thariq Shihipar said on X that Anthropic had tightened safeguards against tools posing as Claude Code because unofficial harnesses caused instability and errors that were hard to diagnose. I think the pricing case is the stronger one, but either way Anthropic is right on the substance.

The enforcement is where Anthropic lost developer trust. The tools broke with no announcement. The consumer terms in effect since October 8 already barred reaching the service "through automated or non-human means" without an API key, but nothing said that clause would now be enforced against coding tools, so developers found out by watching their tools fail and comparing notes in [a GitHub issue on the OpenCode project](https://github.com/anomalyco/opencode/issues/7410), and the explanation arrived afterward on X, along with an admission that automated filters had banned some accounts by mistake. Anthropic said it was restoring those accounts, and the block stayed. Anyone who builds on a platform accepts that the owner sets the terms, which is the tradeoff I described when [OpenAI turned ChatGPT into a place other companies' software runs](/writing/openai-devday-2025-platform-play), but what developers get in exchange is knowing the terms before they're enforced. Silence leaves room for the least charitable reading, and here that reading is lock-in, a company quietly making its own tool the only way to use a plan people already pay for. I don't think that's what happened, but an explanation posted after the tools broke is much harder to trust than a rule published before they did.

The case for doing it quietly deserves a real answer. A warning would have given the tools pretending to be Claude Code a head start on working around the block and invited a rush of heavy use before the cutoff, all to give notice about a use that arguably was never allowed. I take that seriously, and I still think it loses, because a reputation for silent changes costs something every time Anthropic changes anything after that, and Anthropic already has a version of that problem. [A GitHub issue opened on October 7](https://github.com/anthropics/claude-code/issues/9094) pulled together reports from users who said their Claude Code limits had shrunk without notice after Anthropic released Sonnet 4.5 in late September. I haven't seen Anthropic confirm that anything changed, but the complaint was that nobody said anything, and the January 8 block handed developers the same complaint again.

What makes the silence harder to defend is that Anthropic has handled this kind of change well before. When it changed its consumer terms, it [announced the change on August 28, 2025](https://www.anthropic.com/news/updates-to-our-consumer-terms) and gave existing users a dated deadline, later extended to October 8, to choose whether their chats could be used to train Claude, a written rule with a date and a choice attached. When it launched [plugins for Claude Code in October](https://claude.com/blog/claude-code-plugins), it said in a public post that anyone could host a plugin marketplace from their own git repository. Both times the change came in a dated public post before anything broke.

The cutoff of Elon Musk's xAI, reported on January 9 and covered in the same VentureBeat story, is a different case and a more defensible one. According to [Sherwood's account](https://sherwood.news/tech/report-anthropic-cuts-off-xais-access-to-its-models-for-coding/) of reporting by Kylie Robison, xAI staff lost access to Claude through the Cursor coding tool, and cofounder Tony Wu told employees on Slack that the loss would hurt productivity and push xAI to build its own coding product and models. Neither company commented on the record. VentureBeat tied the cutoff to Anthropic's commercial terms, which bar using Claude to build a competing product or service, including competing models. If the report is right, a lab declining to let a direct competitor's engineers build a rival with its model is a policy I'd defend. The trouble is that the two reached people in the same story, and I think that made two separate decisions read as one pattern and made the lock-in reading of the subscription block easier to believe.

Anthropic had a sound rule in January and enforced it without notice. I think the notice is part of the rule, because a sound rule enforced without one still reaches developers as a surprise. An announced cutoff would have cost a few days of arbitrage, meaning heavy users getting the most out of a flat monthly price before the cutoff, plus a short head start for the harnesses to work around it. The silent one cost developer trust at a company whose lead, as [I argued in December](/writing/anthropic-enterprise-lead-narrower-than-40-percent), is deepest with developers and concentrated in coding, which makes developers the group it can least afford to surprise. The announced version would have been a dated post saying that Pro and Max cover Anthropic's own apps and Claude Code, that other tools need an API key starting on a set date, and that anyone caught by the filters by mistake has a way to appeal. That post would have drawn the same line and probably started the same fight about fairness, but developers would have been arguing with an announced cutoff, and that's an argument Anthropic can win on the merits.
